### Category D: Test Expectation ≠ App Design (421 tickets)

These are the bulk of the "Test Case Failed" tickets. Common patterns:

- **Splash screen skipped:** App launched with `--es qa_username --es qa_password`, causing auto-login that bypasses the splash/transition faster than the test expects.
- **Login screen not shown:** Auto-login via intent extras authenticates the user before the test can observe the login screen.
- **"Single row instead of multiple":** The app only displays category rows that have content. With 5 active media types (movie, comic, software, tv_show, book), only those rows appear. Test expected rows for types with zero items.
- **"Hero carousel not visible":** The app does not have a hero carousel; it uses category rows. Test expectation is wrong for the current UI.
- **"No error message for wrong credentials":** App was already logged in via auto-login, so wrong credentials were never entered. Test design flaw.
- **Focus not visible:** Vision model failed to detect the focus indicator in a static screenshot. Focus indicators ARE implemented per Android TV Leanback guidelines.
- **Playback tests:** Most playback tests never reached the player because they got stuck on earlier steps (login screen, home screen, etc.).

## Remediation for Future QA Runs

1. **Screenshot Verification:** Before analyzing any screenshot, HelixQA must verify the active package name (`adb shell dumpsys activity top | grep mFocusedApp`). If the active package is not the target app, mark the step as an infrastructure failure — not an app bug.

2. **ADB Command Validation:** Commands like `curl` that are not guaranteed to exist on Android devices must be pre-checked. Use `which curl` or wrap with fallback logic.

3. **Package Name Consistency:** Ensure the test configuration uses the exact package name (`com.catalogizer.androidtv`) everywhere — no abbreviations or variations.

4. **Auto-Login Awareness:** When QA auto-login intent extras are used, the test plan must account for the fact that splash/login screens will be bypassed. Tests that explicitly verify login flow must launch WITHOUT auto-login extras.

5. **Acceptance Criteria Gate:** Any ticket generated without an `## Acceptance Criteria` section must be rejected by the triage process. The `e07a89f` change enforces this at generation time.

6. **Device Capability Pre-Check:** Tests requiring specific hardware (4K, HDR, HEVC, external audio) must validate device capabilities before running and skip gracefully.

7. **Vision Model Confidence Threshold:** The LLM vision analyzer should require a minimum confidence score (e.g., 0.75) before filing a ticket. Many of the vague UX observations had no confidence score or very low confidence.
