# FIX-QA-2026-04-20-001 — E2E pipeline test false-positive

**Severity:** CRITICAL (Article VII false-positive prohibition)
**Discovered:** 2026-04-20 (Article VII Master Cycle, Phase 2)
**Status:** CLOSED (fix committed + validated)
**Component:** HelixQA / pkg/vision + tests/e2e

## Symptom

`go test ./tests/e2e/...` reported `TestE2E/TestFullPipeline` as FAIL with
`Should NOT be empty, but was []` — and, simultaneously, printed
`✅ Full pipeline test completed successfully` right after the failure. A
100%-pass-looking log line appearing on a failed run is the exact false-positive
anti-pattern Article VII forbids.

## Root Causes

### Bug 1 — fixture mismatch

`processWithVision()` was being fed `testFrames[0]`, an output of
`createTestFrames()` which returns a smooth RGB gradient. The
`pkg/vision.ElementDetector` is contour-based and *correctly* returns zero
elements on featureless images. The step was structurally guaranteed to fail
regardless of detector health — the test was asking a contour detector to
find contours in a flat gradient.

### Bug 2 — non-fatal assertion + unconditional success log

```go
assert.NotEmpty(s.T(), visionResult.Elements)
s.T().Log("✅ Full pipeline test completed successfully")
```

`assert.*` is NON-fatal in testify. When the assertion fails, the step fails
but execution continues — so the success log fired every time, independent of
the assertion outcome. Any reader of the log would see the success line and
conclude the feature was working.

## Fix

`HelixQA/tests/e2e/pipeline_test.go` TestFullPipeline:

1. Route `s.createTestImageWithText()` (white canvas + blue button rect + text
   stripes — features the contour detector is designed to find) through
   `processWithVision` instead of `testFrames[0]`.
2. Convert `assert.NotEmpty` → `require.NotEmpty` with descriptive message.
   `require.*` is fatal, so the success log is now only reachable after every
   upstream assertion genuinely passed.

## Verification

- `go test -mod=vendor -count=1 -run TestE2E/TestFullPipeline ./tests/e2e/...` → PASS.
- `go test -mod=vendor -count=1 ./...` across HelixQA → 100 packages PASS, 0 FAIL.
- Regression entry in `HelixQA/banks/fixes-validation.yaml` guards both invariants going forward.

## Lessons

Every new test MUST:

- Use `require.*` when a later assertion or a success log depends on the current
  assertion passing. Never pair `assert.*` with an unconditional success line.
- Verify the fixture matches what the unit under test is designed to detect.
  Feeding a featureless gradient to a contour detector is structurally broken,
  not a bug in the detector.
