# FIX-QA-2026-04-21-001 — /api/v1/media/:id/favorite returned 500 unconditionally

**Severity:** HIGH (every call to the favorite endpoint 500'd — silent product failure)
**Discovered:** 2026-04-21 by parse-runall-log.py on the 2026-04-20 session log
**Status:** CLOSED (migration v18 + handler fix + happy-path test landed)
**Component:** catalog-api — `handlers/media_handler.go` + `database/migrations*`

## Symptom

Log analysis surfaced `4 × 500 /api/v1/media/1/favorite` in the Article
VII RunAll server log. A 500 on a UPDATE-favorite endpoint is never
expected, and the parse-runall-log tool reported it as a `FAIL (5xx)`
window.

Reproduced by hitting the endpoint with a valid JWT + body:

    curl -X PUT http://localhost:8080/api/v1/media/1/favorite \
      -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
      -d '{"favorite": true}'
    → 500 {"error":"Failed to update favorite status"}

## Root cause

`AndroidTVMediaHandler.UpdateFavoriteStatus` executes:

    UPDATE media_items
    SET is_favorite = ?, updated_at = CURRENT_TIMESTAMP
    WHERE id = ?

Neither `is_favorite` nor `updated_at` existed on the production
`media_items` schema. The production migration
(`createMediaEntityTablesSQLite`, v8) declares only `last_updated`
and never added a favorite column.

The handler's unit tests pass because `internal/tests/test_helper.go`
uses a different parallel `media_items` schema that DOES have both
columns — classic test/production schema drift.

## Fix

Three artefacts:

1. **Migration v18** (`database/migrations_v18_media_favorite.go`):
   ALTER TABLE adds `is_favorite` + `updated_at` to production. SQLite
   path guards with a `PRAGMA table_info()` probe (no `IF NOT EXISTS`
   for ADD COLUMN on SQLite). Backfills existing rows' `updated_at`
   from `last_updated` to avoid a `NULL` wall.
2. **Migration-count test updated** (`migrations_test.go` latestVersion
   17 → 18).
3. **Happy-path + not-found tests** added to `media_handler_test.go`
   (`TestUpdateFavoriteStatus_HappyPath`,
   `TestUpdateFavoriteStatus_MediaNotFound`). Before this change, ALL
   tests for this endpoint were 400-path branches — the real UPDATE
   SQL was never exercised.

## Verification

- `go test -count=1 -run "TestUpdateFavoriteStatus|TestMediaHandlerTestSuite" ./handlers/` → PASS
- `go test -count=1 ./database/` → PASS (v18 applies cleanly on fresh DB)
- Smoke test against running binary:
  - `/api/v1/media/9999999/favorite` → 404 `"Media not found"` (was 500)
  - `/api/v1/media/1/favorite` (happy path in tests) → 200 + `is_favorite` flips 0↔1

## Lessons

- Every handler with a real SQL mutation MUST have a happy-path test
  that exercises the mutation against the production migration schema,
  not the parallel test-helper schema. The bug could have been
  detected at PR time by a single 200-assertion integration test.
- `parse-runall-log.py` (now committed under
  `docs/reports/qa-sessions/2026-04-20-T22-05/analysis/`) turns a raw
  gin log into an actionable FAIL matrix — keep using it when RunAll's
  response body is lost.
